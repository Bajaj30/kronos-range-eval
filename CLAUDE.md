## 1. What this project is
Forecast tomorrow's NIFTY 50 range well enough that a trader can choose an options setup, or no trade, before the open. v1 tests whether Kronos-small beats ATR(14) at this on days after Kronos's public release. Either result is published.

v1 is a narrow slice of Phase 1 / Gate 1 of the Kronos Regime Router design (`../context/`). The resume targets an ML / data engineering role, so the pipeline's rigour is part of the story: snapshots, hashes, generated facts, tests that can fail.

## 3. Ground rules (from spec §3; never broken without writing why)
1. No future in any input. The forecast for day *t* uses only bars dated before *t*, for Kronos and ATR alike.
2. No pretraining overlap. Every tuning and test day comes after Kronos's public release (2 Aug 2025).
3. Freeze before testing. Settings go in PREREG.md and are committed before the test window is touched. The test runs once, and re-runs are counted and reported.
4. Same treatment for both methods. Anything fitted for Kronos is fitted for ATR the same way, on the same days.
5. Each piece of logic lives in one place. Tuning, test and the live page use the same functions.
6. Every quoted number comes from the generated FACTS.md.
7. Seeds fixed, data snapshot hashed. A rerun gives the same numbers.

## 6. Decisions
- **D1–D14 (2026-10-23, user):** accepted as written in spec §5, except D5 below.
- **D5 revised (2026-10-23, user):** at least 100 samples per day, not 30. The final count is set after Chunk 2 measures GPU time, then frozen in PREREG. Because the 10th/90th percentiles of 30 samples are just the 3rd and 27th values, which is too noisy for the coverage verdict. Rejected: 30 (noisy band).
- **D13 confirmed (2026-10-23, from Chunk 0 data):** prices only (OHLC), no volume, for both indices. Because:
  - BANKNIFTY volume is 0 on most rows before 2022;
  - NIFTY volume shows values of 100–500 on normal days;
  - neither can even identify special sessions (FACTS step 00: `volume_zero_rows` and the lowest-volume tables).
  Rejected: volume as an input.
- **D15 (2026-10-23, user):** India VIX becomes a second baseline after Chunks 0–8 ship. Because it is the market's own forecast and the core idea of the full router. Rejected: adding it now (deadline).
- **D16 (2026-10-23, user, cap confirmed):** spend Kaggle GPU on rigour (more samples, more seeds, Kronos-base/mini as separately reported runs), not on more tuning configs. Planned use is capped at 25 h of the ~30 h. Because a failed run needs headroom, and more configs only add chances to get lucky. Rejected: a bigger tuning grid.
- **D17 (2026-10-23, user):** everything for v1 lives in `V1_baseline_testing/`. The working docs are CLAUDE.md, FACTS.md and INTERVIEW.md. INTERVIEW.md stays private.
- **D18 (2026-10-23, user):** data reaches Kaggle as an uploaded Kaggle Dataset (the hashed snapshot). Kaggle never calls Yahoo, and the notebook verifies sha256 against the manifest before use. Rejected: pulling on Kaggle (a different pull means different data).
- **D19 (2026-10-23, Claude; user may override):** raw market data is not committed to the public repo; only the manifest (sha256, rows, pull time) is. Because the redistribution terms for Yahoo and NSE index data are restrictive or unclear, and the manifest still lets anyone check that their own pull matches. Rejected: committing the CSVs (small, but a licensing risk on a public resume repo).
- **D20 (2026-10-23, Claude):** `yf.config.debug.hide_exceptions = False`. Because yfinance's default turns a failed download into an empty table, which we verified with a fake ticker. The deprecated `raise_errors=True` is replaced by this setting.

## 7. Traps (hit while building; full stories in INTERVIEW.md)
- **Known in advance:** spec §9 (14 items).
- **Hit while building:**
  1. **Silent empty download.** yfinance hides errors by default → `hide_exceptions=False` (D20).
  2. **NaN ≠ NaN.** A "mismatch" check flagged exactly the 9 missing-price NIFTY rows → every comparison check must be NaN-aware. When a count equals another count, ask why.
  3. **Special sessions in the bars.** Diwali Muhurat one-hour sessions appear as small-range rows (incl. 2025-10-21, inside the tuning window). A full Sunday Budget session (2026-02-01, inside the test window) is missing from Yahoo → special sessions need a sourced calendar table; volume can't find them (Chunk 1).
  4. **Pipes in Markdown.** A `|` in a description split the FACTS table → `_cell` escapes pipes, and a test covers it.

- Two pulls 33 s apart gave byte-identical files (same sha256).
- **D13 confirmed:** OHLC only (§6).

**Checks that could fail, all passing (23 tests):**
- the seeded 10-row table gives exact defect counts;
- the tester fails on a wrong count or a missing key;
- each defect is found alone on its own row;
- the IST date survives a UTC timestamp;
- the gap threshold works;
- the sha256 known vector matches;
- a changed byte changes the hash;
- a second run verifies and never re-downloads;
- a tampered file is refused on every read;
- an empty source leaves no snapshot;
- a partial folder is rebuilt;
- FACTS render is deterministic;
- undefined or conflicting groups are refused;
- pipes are escaped.
